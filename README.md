# Receptes

Русскоязычный сайт о домашней выпечке. Финальный дизайн — дарк академия «Библиотека».

- Сайт: https://receptes.z0.lv/
- Админка: https://receptes.z0.lv/admin/
- Репозиторий: `DeadRaaat/cookbook`, ветка `main`.

## Домен и публикация

В репозитории откройте **Settings → Pages**:

1. В **Build and deployment → Source** выберите **GitHub Actions**.
2. В **Custom domain** укажите `receptes.z0.lv` и сохраните. Для публикации через Actions одного файла `CNAME` недостаточно — домен нужно также указать в настройках Pages.
3. В DNS зоны `z0.lv` создайте запись **CNAME**: имя `receptes`, значение `deadraaat.github.io` (без `/cookbook`). Если используется Cloudflare, на время проверки домена и выпуска сертификата включите режим **DNS only**.
4. После проверки DNS и выпуска сертификата включите **Enforce HTTPS**. До этого онлайн-вход по HTTP намеренно недоступен.

После push в `main` GitHub Actions проверяет данные и публикует сайт. Сохранение в онлайн-админке также создаёт коммит в `main` и запускает публикацию. Обновление сайта обычно занимает несколько минут; состояние видно во вкладке **Actions**.

В артефакт попадают только `index.html`, `CNAME`, `assets`, `data` и `admin`. Исходники серверных инструментов, `node_modules` и личный оригинал фото не публикуются.

## Онлайн-админка без отдельного сервера

Админка использует Decap CMS и напрямую обращается к GitHub API. Для входа вместо OAuth используется **fine-grained personal access token**. Это специально добавленный экран входа поверх штатного GitHub backend Decap. Отдельный сервер, OAuth App и Client Secret не нужны.

### Первый вход

1. Под аккаунтом, имеющим право записи в `DeadRaaat/cookbook`, откройте https://github.com/settings/personal-access-tokens/new.
2. Укажите имя, например `Receptes editor`, и срок действия (рекомендуется 30–90 дней).
3. В **Resource owner** выберите **DeadRaaat**.
4. В **Repository access → Only select repositories** выберите только **cookbook**.
5. В **Repository permissions** задайте **Contents: Read and write**. **Metadata: Read-only** добавляется автоматически. Другие права, включая Administration и Workflows, для редактирования рецептов не нужны.
6. Сгенерируйте токен и сохраните в менеджере паролей. Вставьте его в форму на https://receptes.z0.lv/admin/.

**Не присылайте токен в чат и не добавляйте его в файлы сайта.** Он хранится только в памяти открытой вкладки: после обновления страницы или закрытия вкладки войдите заново. Decap сохраняет в localStorage только профиль без токена; черновики рецептов могут сохраняться в IndexedDB. Не пользуйтесь админкой на чужом компьютере. При утечке отзовите токен в GitHub. Токен даёт запись в выбранный репозиторий целиком — GitHub не позволяет ограничить его только папками с рецептами.

Код Decap загружается с закреплённой версией и проверкой целостности SRI. Сетевые запросы с токеном идут непосредственно в GitHub по HTTPS.

### Рецепты

На самом сайте в шапке есть кнопка **Добавить рецепт**, видимая и на телефоне. Она открывает **всплывающее окно прямо на странице**, без перехода в админку. Заполните название, категорию, время, описание, ингредиенты и приготовление, при желании загрузите фото. Категорию можно выбрать из подсказок или вписать новую.

В разделе «Доступ к публикации» введите ограниченный GitHub-токен (инструкция доступна в самом окне). Нажмите **Опубликовать рецепт**. Токен останется только в памяти этой вкладки; повторно вводить его для следующего рецепта не нужно. Без токена с правом записи посетитель не может сохранить рецепт.

Форма использует тот же механизм хранения, что и Decap: GitHub API и коммит в `main`. Рецепт, новая категория и фотография сохраняются одним коммитом, затем GitHub Actions обновляет сайт для всех. У автора новая карточка появляется сразу в открытой странице; после перезагрузки до завершения деплоя её ещё может не быть. При одновременном редактировании коллекции форма не перезаписывает чужие изменения: текст остаётся в окне, а публикацию можно повторить. Если GitHub не подтвердил запись, повторная отправка блокируется до проверки коммитов, чтобы избежать дублей.

Закрытие окна не удаляет введённый текст до перезагрузки страницы. При попытке уйти с несохранённым рецептом браузер предупреждает об этом. Фото: JPG, PNG или WebP до 8 МБ. Предпросмотр фото локальный и не загружается в сторонние сервисы.

Откройте **Мои рецепты → Коллекция рецептов → Добавить рецепт**. Заполните название, категорию, время, описание, ингредиенты и приготовление. Фото необязательно. Нажмите **Опубликовать**. Шаги можно писать с новой строки — переносы сохраняются на сайте.

Рецепты хранятся в `data/recipes.json`, фотографии — в `assets/uploads`. Список поддерживает изменение порядка и удаление рецептов.

### Категории

Откройте **Категории → Мои категории → Добавить категорию**, введите название и опубликуйте. После этого выберите её в рецепте. Категории хранятся в `data/categories.json`; их порядок задаёт порядок кнопок на сайте. Название «Все» зарезервировано.

При переименовании или удалении категории обновите и соответствующие рецепты. До этого старое название останется в фильтрах, чтобы рецепты были доступны.

### Необязательный OAuth

Если впоследствии понадобится обычная кнопка входа через GitHub, можно подключить доверенный Decap-совместимый OAuth-сервис: укажите его HTTPS-адрес в `admin/settings.json`, поле `oauth_url`. Client Secret хранится только на стороне этого сервиса. Пока поле пустое, используется вход по токену.

## Локальная работа

```sh
npm ci
npm run serve
```

Сайт: http://localhost:8000/. Открытие `index.html` через `file://` не поддерживается, поскольку данные загружаются из JSON.

Для редактирования **локальных файлов** в отдельном терминале запустите `npm run cms`, затем откройте http://localhost:8000/admin/. Локальный Decap работает только на `127.0.0.1:8081`; не выставляйте этот порт в интернет. Изменения локальных файлов нужно закоммитить и отправить в GitHub.

Если локальный Decap не запущен, админка предлагает вход по токену: в этом случае редактируется **GitHub**, а не локальные файлы.

## Проверки и оформление

`npm run check` проверяет поля рецептов, категории и наличие фотографий; `npm test` запускает тесты данных, `npm run test:auth` — проверки входа, `npm run test:publish` — проверки публикации из всплывающего окна. Проверки также выполняются перед публикацией. HTML в тексте рецептов не исполняется. Пути к фото работают на своём домене и в подпапке GitHub Pages.

В локальной зависимости Decap остаётся предупреждение npm audit низкой серьёзности для `@hapi/joi`. Локальный сервер ограничен loopback-адресом и не публикуется. `simple-git` закреплён на исправленной версии через `overrides`.

Финальные стили — `assets/library.css`. На главной используется личное фото владельца сайта: `assets/homemade-bread.jpeg`. Оригинал хранится локально и исключён из Git.
